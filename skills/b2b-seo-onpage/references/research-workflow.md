# 从行业词库到这一页的改稿

完整单页优化读本文件。语义判断由 Codex 完成；脚本负责文件、引用、上下文与交付一致性，不自动决定搜索意图或排名机会。

## 0. 先辨明是改已有页面，还是为关键词选承接页

已有 URL 时直接读取并识别页型；用户不必先填“类目/详情/文章”。没有页面时先从主词、市场/语言和真实业务出发，用 SERP 判断采购任务，再建议页型。已确认页型保留；混合 SERP 可以支持多种形式，不把某个词尾映射为固定模板。

例如 `mini excavator manufacturer` 可能涉及供应商筛选、品牌产品选择或厂家比较。应区分企业首页、产品分类、公司/制造能力介绍与比较文章；`manufacturer` 也不证明本企业是制造商。核其真实身份、产品范围和可提供的证明。若现有站点可能有多个承接页，先核相关首页/分类页的职责，不能仅因标题同含主词就宣布“内耗”，也不据此新建重复页面。

资料不足时交“初步页型/意图判断”：列观察、推断和缺口，说明当前能否继续。只有关键词时不要求先造 URL；正式单页简报确定后再接下文。未收到行业词库时，不运行或声称完成完整页研究；可独立演示已限定的标题/标题层级改稿，但原整页任务保持未完成。试测不能用合成词库或历史可见样本替代用户要求的完整词库。

## 1. 接收链接，整理一次，按页复用

进入完整优化但尚无可读词库时问：「请给我行业词库的 CSV/表格链接，或原始导出文件夹的位置。应包含 Top 20 竞品自然排名 1–30 的关键词，以及产品种子词扩展表；未合并也可以，我来整理。」同时复用已知页面、识别/已定页型、主词、目标国家/语言、业务事实，不重复索要。资料可以同一条消息提供，不规定必须先交页型或先交关键词的问答顺序。

- 云端链接优先用可用的对应文件工具读取；必要时使用浏览器。链接权限不足时指出哪份打不开。用户不必公开分享，沿现有授权访问即可。
- 竞品表保留 domain、keyword、position、ranking_url、国家/语言、日期及可得指标。种子表保留 seed、keyword、扩展方式/分组、国家/语言、日期和可得指标。表头自动识别；无法判断时只澄清会改变结果的字段。
- 核用户确认的 20 个竞品及实际收到名单，筛选位置 1–30，记录原行数/有效行数/缺 URL/缺位置/导出上限/缺竞品。不能用工具总行数冒充已取得行数。只有最终合并 CSV 也可用，但缺失来源和覆盖信息要标待核，不能猜回原始关系。
- 统一空格、大小写和编码后在同国家/语言内去重。保留原词；型号、单位、连字符、否定词、品牌、买/租、新/二手等不得无依据合并。语义近义词属于分组，不是字符串去重。
- 保存关键词主表、逐条来源关系、指标观察与原始文件。一个词出现在多个竞品或多个 URL，保留每条关系和位置；搜索量不是这些行的和。指标有冲突时保留提供方/数据库/日期，可选一个适用观察供展示并说明理由。
- 若本环境有行业词库 Skill，可复用其 `library.py` 做字段映射和去重；排名/URL 等原始字段继续保留并形成关系表。只安装 On-page 时用环境内可用表格/本地处理能力完成同样工作，不依赖某个兄弟目录。归一化表、关系表和来源登记由 Codex 生成。

两类来源与 20 家覆盖是本工作流的完整性要求；实际不足时照实交部分结果，不捏造补齐。首次整理保存可复用文件及哈希；后续同项目页面按相关词检索，不重复要求导出整个行业。

## 2. 判断“哪些词属于这一页”

从已选主词、产品实体、同义表达、属性/单位、采购任务和排名 URL 找候选组；同时查看相关词在竞品哪些页上排名。避免仅字面包含主词，也避免最高量的泛词挤掉型号主词。

对候选逐组判断业务适配、意图、页型、范围与本页可提供的事实。标记 `include / other_page / exclude / review`，说明理由、来源行和预定模块；不用的词也给去向。相关词不等于应写进同一页面。数据规模较大时先可复现筛选，再人工语义审阅候选，说明筛选范围与未审部分。

需要核同页归组时，查代表辅助词的目标市场结果，比较与主词的自然结果 URL/页型重合以及实际任务；重合只是证据，不规定统一百分比。库内没有的真实产品表达可作 `editorial` 候选，工具新查到的词标 `web`；不能给编辑候选编造搜索量。没有市场指标不等于没有采购价值。

示例仅演示判断：若目标是销售新机的 `1 ton excavator` 类目页，`1 tonne mini excavator` 可能同组；尺寸/重量可进入选型比较，但型号专属值要注明型号；租赁、二手、无关品牌词通常排除或归其他页；`how to operate ...` 可能适合指南页。最终归属要看实际业务、词库与 SERP，不把这个示例当作预定答案。

## 3. Computer Use 补充研究

用户指定网页版时直接使用该入口及已登录会话。官方站、共享账号或第三方代理入口都先看实际页面，不硬编码域名/选择器，不要求用户换购 API 或 MCP。仅界面长得相似不能认定数据来自官方 API；记录实际入口的无凭据地址、页面显示的工具名和数据来源可信范围。

先识别平台实际访问限制。若页面明确禁止自动化访问/抓取，说明看到的具体限制，改为引导用户手动导出所需报告；不要把“账号能登录”等同于“这个入口允许自动操作”。共享账号本身不决定取数方式。浏览器自动操作仅用于可正常使用的入口，不规避平台限制；收到原始导出后仍自动完成所有本地研究与改稿步骤。

1. 识别当前工具、查询词、数据库/市场、语言与筛选状态。先读状态再操作，查询后确认页面确已更新。
2. Keyword Magic：从主词/必要变体开始；按问题、广泛/词组/完全/相关模式及包含/排除词筛选。只展开与本页决定有关的组；不同匹配方式和问题词是研究入口，不直接变成全部 H2/FAQ。
3. 保存可得的 keyword、volume、KD、intent、CPC、分组及导出日期；未知指标留空。标签与意图由工具提供，最后仍用 SERP 和任务判断。
4. 能导出优先导出，核文件名、表头、行数、查询/筛选、数据库和截断。不能导出则按需要读可见行/有限分页，保存来源与实际数量；界面总数不等于采集数。下载/页面读取都保留检查点，避免重复消耗额度。
5. Keyword Overview/SERP 区域取得排名 URL、位置与日期；若不可用，可读取用户导出或目标市场搜索结果。遇登录、验证码、订阅上限或共享会话失效时说明具体阻碍，让用户完成所需操作，继续不依赖该分支的工作；不绕过限制或无限重试。

会话密钥、cookie、密码及 URL 中的访问参数不写入报告或公开包。只读研究通常不需要创建工具项目；如确需额外付费或改变账号设置，按实际授权处理。不能把“工具已打开”报告成“数据已经取齐”。

## 4. 分开做 SERP 与排名页面分析

**SERP 观察表：** 查询词、搜索引擎/提供方、目标与实际国家/语言、设备（可知时）、时间、来源、自然位置、URL、展示标题、页型、可观察特征。默认争取本词自然结果前十；广告、购物、PAA、视频等单列。同 URL 多个实际位置保留观察，独立页面计数另算。通用搜索/工具缓存/历史导出/Google 实时页面分别注明；无法验证市场或排名只能叫样本。

请求参数指定国家/语言不等于实际地域已验证；检查跳转后的搜索域名、界面语言与可见位置提示，记录不一致或未知。只见九条就记九条，不拿广告或另一次搜索补成前十。搜索发现的补充参考页单列，不能填进本次排名表。

**判断：** 主导及混合意图、采购任务、常见页型与内容形式、目标页是否适合。已定型号页面对泛产品目录 SERP 时保留型号身份，解释冲突及可选处理，不能自行升格成类目页。自然排名结果与用户的直接商业竞品不一定相同；大型平台、百科、制造商各自作用不同。

**实际读代表页面：** 通常选 3–5 个能解释主要页型/差异的自然结果，按信息增益调整数量并写选择理由。记录实际 URL、标题/H 结构、关键模块、规格/比较方式、独有资料、图片/视频用途、内链与询价路径。读失败列明，不能依据 SERP 摘要假装分析了全文。

对照表必须连接「竞品可观察优点 → 本页现状/缺口 → 建议保留/新增/改进 → 企业事实来源」。频繁出现的模块可能是基本需求，但不能推断它导致排名；竞品未写某点也不自动是机会。用采购任务和企业可验证资料决定差异化，不拼贴同行大纲、参数、案例或资质。

研究 Title 时补看同一样本的展示标题、实际 `<title>` 与 H1，缺哪项就留空；提炼页型、内容形式、角度和具体承诺。分别记“本页也需满足的共性需求”“本企业有证据提供的差异”“不适合本企业的做法”，不要把 SERP 展示标题当作落地页原始字段。标题或模块常见程度不等于其排名贡献；本页不能兑现的格式/卖点不借用。具体取舍落实到[Title 方法](title-and-snippet.md)和模块简报。

复用研究需核同主词/市场/语言、页型、来源范围、时间和业务是否变化；不设统一过期天数。只有库需要刷新时才更新库，只有争议词需要补查时不重跑整个行业研究。

## 5. 形成可写作的页面简报

简报先给结论：页型/意图是否相容、主辅词及排除词、受众任务、本页提供的价值、依据和未决项。然后为每个模块写建议标题、回答的问题、用哪些词、需要什么证据、保留/新增/改善及内链目标。长度由问题和事实决定，不抄竞品字数均值。

把最重要的采购任务放在容易到达的位置，并明确本页现有优点与应保留部分。每个新增模块应能说明它解决什么缺口、实际资料从哪里来；不能仅因同行有、工具给了相关词或想达到某个字数就添加。标题承诺必须能在简报和实际稿件中找到对应内容。

| 页型 | 研究应落到的内容任务 |
| --- | --- |
| 企业首页 | 企业与产品定位、主要产品入口、可信能力摘要及下一步采购路径；不过度展开每个型号或重复整个目录 |
| 公司/制造能力介绍页 | 企业身份、真实制造/检验流程与可核验资料；与首页分工，不能只把泛产品词堆成另一份首页 |
| 类目页 | 范围与差异、真实产品卡/比较、选型维度、兼容用途、采购条件和相关型号入口 |
| 产品详情页 | 保持型号身份、核实规格/尺寸/配置、适配与限制、下载资料、相关配件/型号及询价所需信息 |
| 文章页 | 具体问题与直接回答、证据/步骤/比较、适用条件、第一手经验或资料、相关产品与下一步阅读 |
| 能力/应用页 | 工艺或场景条件、可验证能力、边界、真实案例或测试依据、适用产品和询价资料 |

FAQ 按真实剩余问题设置，不自动把所有问题词改成 FAQ；无事实支持的模块标待补，不让标题暗示企业已有该能力。已有架构模块先保留，调整说明理由。具体 Title/description/H1、正文和关键词位置沿用[改稿方法](keyword-and-heading-workflow.md)。文章全文可把同一简报交给可用内容 Skill，继续完成本次授权任务。

## 6. 完成条件

- 词库已可读，两类来源、Top 20 覆盖及清洗/聚合可追溯；本页候选有取舍、依据与落点。
- 有与实际市场/语言匹配的 SERP 证据，以及实际阅读过的代表页面；覆盖不足明确标部分完成。
- 有从研究结论推导的模块简报与实际改稿，企业主张独立核实；未使用或被排除的词不混入建议辅助词。
- 研究、改稿、保存、前台回读和 SEO 效果分别说明。脚本 `documented` 只说明记录具备结构与引用，不自动证明研究结论正确；`partial` 不能报完整，`simulation` 不能报真实实访。

结构化输入由 Codex 整理，见[研究数据接口](research-contract.md)。用户始终用自然语言和资料链接。
